### О проекте

Archive Manager работает внутри файлового менеджера AutoJs6, а не заменяет его. Поддерживаемые архивы используют список, строку пути, тему, средства просмотра, выбор, прогресс и обновление каталогов хоста. Отдельная страница управления нужна только для расширенных настроек и операций записи.

### Доступно сейчас

- Просмотр ZIP/JAR/AAR/WAR, 7Z, RAR4/RAR5 и семейства TAR в штатном списке AutoJs6 с внутренним путем, поиском, сортировкой и навигацией Назад.
- Предпросмотр читаемых документов, изображений, аудио и видео существующими средствами хоста без предварительного извлечения всего архива.
- Извлечение всего архива, текущей внутренней папки или выбранных элементов с прогрессом, отменой, безопасными именами при конфликте, проверкой и откатом до публикации.
- Открытие и извлечение зашифрованных ZIP, 7Z и RAR со штатным запросом пароля; ошибочный пароль можно исправить без потери текущего пути.
- Исправление кодировки имен ZIP прямо в строке пути хоста; тот же сеанс только для чтения перестраивает индекс и по возможности сохраняет текущий внутренний путь и доступный выбор.
- Просмотр и извлечение полных стандартных наборов `.z01 + .zip`, современных WinRAR `partN.rar`, нумерованных `.zip.001` и `.7z.001` через ограниченные дескрипторы соседних томов, разрешенные хостом; отсутствующий или измененный том дает явную ошибку.
- Создание ZIP, 7Z, TAR, TAR.GZ, TAR.XZ, TAR.BZ2 и TAR.ZST из одного элемента или выбора с общим родителем; ZIP также поддерживает AES-256, стандартные тома и отдельный архив для каждого элемента.
- Стандартный разделенный ZIP и отдельное сжатие каждого элемента публикуют все проверенные физические выходы одним восстанавливаемым пакетом; сбой или перезапуск хоста не показывается как успешный частичный результат.
- Редактирование обычного однотомного ZIP через проверенную пересборку: добавление файлов или дерева папок, создание пустых папок, переименование и удаление с атомарной заменой только после полного повторного чтения.
- Изоляция опасных имен в режиме только для чтения, структурные и ресурсные ограничения перед записью и прямое чтение seekable-дескриптора хоста, когда это возможно.
- При необходимости полный исходный выбор можно переместить в корзину хоста только после проверки и фиксации всех физических выходов. Параметр по умолчанию выключен, а изменение исходников или неполное доказательство выходов останавливает операцию до удаления исходных данных.

### Текущие форматы

Текущая версия распознаёт следующие расширения для просмотра и извлечения:

```text
zip, zip.001, jar, aar, war, 7z, 7z.001, rar, tar, tar.gz, tgz, tar.xz, txz, tar.bz2, tbz2, tar.zst, tzst
```

Текущая версия может создавать следующие форматы:

```text
zip, 7z, tar, tar.gz, tar.xz, tar.bz2, tar.zst
```

> Для нативной интеграции требуется соответствующая сборка AutoJs6 6.8.0 с Explorer Action v16 (код версии 5276 или новее). RAR и многотомные архивы доступны только для чтения; редактирование ограничено обычными однотомными `.zip`. Стандартный разделенный ZIP открывайте через последний `.zip`, современный набор WinRAR через первый `partN.rar`, а нумерованный ZIP или 7Z через том `.001`, разместив все обязательные тома в одной папке. Шифрование имен при создании и редактирование содержимого 7Z, RAR или TAR пока не поддерживаются.

### Использование

1. Установите Archive Manager и включите его в Центре плагинов AutoJs6.
2. Нажмите основное действие поддерживаемого файла или выберите Открыть архив, затем просматривайте его как обычную папку с помощью строки пути хоста.
3. Используйте действие извлечения в строке пути для текущей внутренней папки или действие кодировки для исправления имен ZIP, долгое нажатие для выбора элементов или Извлечь в... в меню файла для всего архива. При необходимости появится запрос пароля.
4. Выберите Сжать... для файла или папки либо отметьте несколько элементов одного каталога и используйте действие нижней панели. Чтобы очистить исходники после успеха, явно включите выключенный по умолчанию параметр перемещения исходных элементов в корзину после сжатия.
5. Выбирайте Управление архивом... только для добавления, переименования или удаления содержимого обычного однотомного ZIP.

### Разрешения и данные

Archive Manager не запрашивает разрешения на хранилище или сеть. Хост передает краткоживущие дескрипторы только для чтения и транзакции, привязанные к UID плагина, поэтому произвольный путь выбрать нельзя. Explorer Action v11 передает пароль только в ограниченном синхронном запросе и ничего не сохраняет. Explorer Action v12 добавляет только ограниченный каталог соседних томов, одобренных хостом и привязанных к сессии, с непрозрачными ID и повторной проверкой идентичности. Explorer Action v13 повторно индексирует только тот же подготовленный источник и сохраняет прежнее состояние до готовности полного нового индекса. Explorer Action v14 сопоставляет только ограниченные составные суффиксы вроде `.zip.001` и `.7z.001`, но не произвольные файлы `.001`, и повторно использует каталог v12 без доступа к каталогам или путям. Опасные пути изолируются, вывод проверяется до публикации, а подтверждение бюджета не отключает структурную безопасность.

Explorer Action v15 объединяет только проверенные новые выходы одной сессии в восстанавливаемый пакет не более чем из 128 элементов. Explorer Action v16 позволяет хосту повторно проверить исходники и выходы и переместить исходники в корзину только когда плагин передает полный исходный выбор в точном порядке и все зафиксированные транзакции выходов. Хост синхронизирует восстанавливаемую копию и сохраняет запись до удаления исходных данных; плагин не получает произвольных путей или прямого удаления. Потерянный ответ Binder разрешается запросом того же идемпотентного конечного результата, без повторения перемещения.

### Примечания к выпуску

#### v2.9.0

_2026/08/27_

- `Примечание` Для этого выпуска требуется соответствующая сборка AutoJs6 6.8.0 с Explorer Action v16 (код версии 5276 или новее)
- `Добавлено` В форму сжатия добавлен выключенный по умолчанию параметр перемещения исходников в корзину после сжатия; он выполняется только после проверки и фиксации всех физических выходов
- `Добавлено` Explorer Action v16 принимает только полный исходный выбор в точном порядке и все зафиксированные транзакции выходов, после чего хост повторно проверяет идентичность исходников и выходов перед использованием корзины
- `Исправлено` Хост теперь синхронизирует восстанавливаемую копию и сохраняет запись корзины до удаления исходника; если каталог удален лишь частично, восстанавливаемая копия сохраняется как единственные данные восстановления
- `Улучшено` Этап корзины нельзя отменить, а результаты зафиксировано, требуется восстановление, ошибка и неизвестно показываются отдельно; потерянный ответ Binder приводит к запросу конечного состояния хоста без слепого повтора

#### v2.8.0

_2026/08/27_

- `Примечание` Для этого выпуска требуется соответствующая сборка AutoJs6 6.8.0 с Explorer Action v15 (код версии 5276 или новее)
- `Добавлено` Стандартный разделенный ZIP и отдельное сжатие каждого элемента теперь завершают запись и обратную проверку всех выходов до единой восстанавливаемой пакетной публикации Explorer Action v15
- `Исправлено` Создание нескольких выходов больше не оставляет зафиксированные частичные результаты при обычных сбоях; Explorer обновляется и успех сообщается только после фиксации всего пакета
- `Исправлено` Переключатели параметров сжатия теперь правильно отображаются и нажимаются в Android 7, а не выглядят как обычные текстовые подписи
- `Улучшено` Хост до публикации надежно записывает родительский каталог и идентичность каждого временного файла; сбой или перезапуск откатывает только совпадающие элементы, а измененные извне файлы сохраняются для ручного восстановления

#### v2.7.0

_2026/08/27_

- `Примечание` Для этого выпуска требуется соответствующая сборка AutoJs6 6.8.0 с Explorer Action v14 (код версии 5276 или новее)
- `Добавлено` Полные нумерованные наборы `.zip.001` и `.7z.001` теперь можно просматривать, предварительно открывать и извлекать через том `.001`; они остаются только для чтения
- `Добавлено` Explorer Action v14 добавляет ограниченное сопоставление составных суффиксов имен и повторно использует привязанный к UID источник соседних томов v12, не распознавая произвольные файлы `.001`
- `Исправлено` Android 7 объединяет разрешенные хостом нумерованные тома ZIP в один приватный локальный файл перед путем совместимости Zip4j, поэтому корректные наборы больше не помечаются как поврежденные
- `Улучшено` Номера соседних томов ограничены диапазоном от `.002` до `.128`, и все предоставленные тома должны идти подряд; reader точно сообщает следующий отсутствующий том, повторно проверяет идентичность вокруг материализации и не заявляет внутреннее редактирование
